# 本題を直接伝える

## たとえを選ぶ

まず、何を理解してほしいかを決めます。その内容を直接書き、足りない場合にだけ例を検討します。例がなくても失敗ではありません。

題材を知っていることと、その仕組みを知っていることは別です。必要な関係が読者に既知かを考えます。不明なら、そのことを記録して直接説明を選びます。元の仕組みを説明する案も可能ですが、本題より重くなるなら採用しません。

例を残す場合は、何が本題に対応するかを伝えます。複数の対応をまとめて列挙せず、必要な順に扱います。設定を増やさないと成立しない例や、誤った推論を招く例は捨てる候補です。例から本題へ戻る箇所も明らかにします。

具体例、関係を借りる類推、印象を残す表現上の比喩は区別します。表現比喩に、説明用の類推と同じ既知性を強制しません。ただし、効果と誤解の可能性は検討します。架空の例を実際の経験として書かず、新しい事実には既存の資料管理を適用します。

## 分かってから先へ

ひとつの意味を示したら、読者が受け取れるところまで書きます。なぜ大切なのかが分からなければ、その理由を伝えます。そのうえで次の意味に進みます。句点を増やすだけで、説明していない概念を次々に導入しないようにします。

「説明し、例を出し、留保を付け、発見まで述べた」は、詰め込みの指摘なら「説明から発見までを書いた」で足りる場合があります。途中の項目が判断に必要でなければ省きます。ただし、手順や安全条件のように必要な項目まで省いてはいけません。

前に伝えた意味を、違う角度から繰り返して構いません。新情報が増えなくても、理解や実感が進むなら残します。同じ対象の呼び名を次々に変えたり、言い換えのために断定を足したりしないようにします。反復の回数、概念数、段落長は固定しません。「説明、理由、言い換え」を毎段落の型にもせず、既に伝わっている理由は足しません。

## 編集v4の記録

新規編集要求はv4です。explanation_review.examplesへ、検討した例だけを記録します。空ならno_examples_reasonに直接説明で足りる理由を書きます。採用数のノルマはありません。

各例は次の項目を持ちます。これらは内部判断であり、本文へ列挙しません。

```json
{
  "id": "e1",
  "source_ids": ["u001"],
  "goal": "読者に理解してほしい意味",
  "plain": "たとえを使わない実際の候補文",
  "candidate": "比較する例の実際の候補文",
  "kind": "analogy",
  "familiarity": {"status": "known", "basis": "元の関係が既知だと判断した根拠"},
  "mapping": "本題と対応する関係 または表現比喩の効果",
  "setup_reason": "追加した設定が必要な理由 または不要な設定を省いた理由",
  "misreading": "生じ得る誤解とその対処",
  "choice": "example",
  "choice_reason": "直接案と比較して残す理由",
  "output": {"paragraph_id": "v001", "quote": "採用した本文の正確な引用"},
  "return_to_topic": {"paragraph_id": "v002", "quote": "本題へ戻る箇所の正確な引用"}
}
```

kindはdirect_example/analogy/expressive_metaphorです。familiarity.statusはknown/unknown/explainedで、explainedは必要な仕組みを本文で説明した場合です。choiceはplain/example/omitで、omitにはoutput不要、exampleにはreturn_to_topicが必要です。対応と意味の妥当性は機械判定ではありません。

## 読者の回答を待つ

reader_checksにはid、target（paragraph_id/quote）、question、expected_meaning、misunderstanding、example_idsを置きます。本題を説明し直す質問を最低一つ用意し、採用した例は全ていずれかの質問へ対応付けます。expected_meaningは本文に基づく判定基準で、読者へ質問するときは見せません。別場面への適用も、必要な場合に尋ねます。

回答を生成時に捏造しません。読者への質問を用意しただけならreader_evaluation.statusはpendingです。モデルによる試答は実読者の回答と区別します。実際の回答が届いた場合だけ、次の形で端末内に保存します。

```json
{
  "article_hash": "result.jsonのreader_evaluation.article_hash",
  "origin": "reader",
  "observation_source": "回答を受け取った経路や日時 個人名は不要",
  "answers": [{"check_id": "r1", "answer": "読者が実際に述べた回答"}]
}
```

`natural-japanese editor-reader-feedback result.json --feedback answers.json`を使います。モデルの試答ならoriginはmodelです。一部の質問だけに答えた記録も残せます。「分からない」という回答も有用です。保存を望まれない場合は実行しません。

次回の編集ではcontextのmemory_indexから、同じ原稿や用途の読者記録だけを読みます。どの意味が伝わらなかったかを、該当版の本文へ戻って考えます。個人の不採用例を全利用者の禁止規則にはしません。保存コマンドは原稿を自動改稿せず、品質向上の自動採点もしません。

研究の出典と確認範囲はリポジトリのdocs/analogy-research-20260908.md、実装仕様はdocs/editorial-explanation-spec.mdに記録しています。
