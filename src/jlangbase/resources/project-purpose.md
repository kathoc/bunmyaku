# 書きながら考えを深める

bunmyakuは、文章を書きながら考えを深める生成の仕組みです。書いたことで気づきが生まれたら、語り手の見方と、その先の構成を更新します。推敲は、そうして生まれた文章を読者へ届けるための工程です。

これはプロジェクトの目的の正本です。最新の修正依頼や個人の嗜好とは分けて扱います。目的自体の変更は利用者へ変更案として示し、明示的な確認を得てから行います。部分機能の改善を、目的変更の承認と解釈しません。

## 作業を位置づける

実装やbunmyakuの紹介記事を始める前に、今回の仕事が目的のどの部分を支えるかを書きます。推敲の改善なら、その範囲を明示します。一般の依頼原稿の主題をbunmyakuの説明へ変更する指示ではありません。

purpose-startでtask、area、contribution、non_goalsを記録します。areaはgeneration/editing/explanation/maintenance。目的の文面とハッシュを添えて端末内へ残します。既存の作業記録を上書きしません。直近の指摘は修正履歴へ残し、目的の文面を更新する理由にしません。

## 構成の段階で照らす

bunmyakuを紹介する記事では、本文を書く前に次を考えます。

- 書く途中の気づきが、その先の文章や構成を変える例が中心にあるか。
- 修正前と修正後の例だけで、生成の仕組みを説明したつもりになっていないか。
- 事実と見方を分け、毎段落に逆転や発見を強制していないか。
- 推敲、保存、導入の説明は、中心の仕組みを補う位置にあるか。

作業記録は目的の一致を保証しません。機械が調べるのは記録の存在と形式であり、位置づけの妥当性は人とAIが内容を読んで判断します。
