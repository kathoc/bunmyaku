# 敬体の基調と文末の単調さ

## 目的と原因

症状: note記事で「ます・です・ません」による説明の着地が続く。
原因: 敬体の既定はあるが、語りの役割に応じた文の接続・省略・文体移行の手順が弱く、一つずつ完結する説明が蓄積した。

## 採用する仕様

配布済み共通手順・編集手順・スキルからeditorial-register.mdを参照する。生成と推敲の指示層に実装し、Pythonの判定器やJSON契約は変更しない。
敬体は文章全体の基調。記事・随筆では観察、内的な問い、実感に常体を許す。手順・警告・明示された厳密な文体統一は優先。
修正順は意味の重複削除、同じ対象を追える接続、文の切り方、必要時だけ語り方の変更。判断は既存cadenceのeffect/alternative/choice_reasonと変更記録へ残せる。

## 比較した案

1. 文末の置換: 安価だが意味・距離感を壊すため不採用。
2. 敬体と常体の交互配置: 容易だが別の単調さを生むため不採用。
3. 文末比率の閾値: 測定容易だが品質の代用になるため不採用。
4. 取捨選択と文の役割から編集: 判断が必要だが原因に届くため採用。
5. 新たな自動採点器: 今回の問題には不要。意味判断の保証にならないため見送り。

## 完了条件と範囲

指示の各入口を接続し、note記事の改稿と選択理由を残す。図版6点と表紙は維持。読者評価・音声評価・自動検証を実施済みとは扱わない。
