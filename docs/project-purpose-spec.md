# 目的と作業を分ける

## 原因と目的

利用者の修正依頼に合わせて推敲工程を改善するうちに、紹介記事まで推敲ツールの説明になりました。生成ループの全文を読み、本文から発見を抽出して認識と構成を更新する処理は存在する一方、プロジェクトの目的を各作業の入口へ渡す契約がないことを把握しました。

## 採用案

小規模な接続変更として、目的の正本、要求への同梱、作業開始記録、紹介構成の点検、修正履歴との分離を採用します。全原稿への目的宣言の強制、目的一致の自動採点、作業を全件止める必須承認は見送ります。一般原稿の内容や作業量を不必要に変えないためです。

resources/project-purpose.mdを唯一の目的正本にします。purpose.pyで本文とハッシュを取得し、生成・振り返り要求、編集要求、contextへ渡します。purpose-startはtask/area/contribution/non_goalsを端末内へ追記し、目的変更を含む入力を拒否します。利用者が明示承認した目的変更そのものは、正本の別編集として扱います。

機械は意味上の一致を保証しません。作業開始コマンドを呼ぶことはスキルの手順であり、すべての操作への強制ゲートではありません。既存stateの形式は変更しません。

## 今回の位置づけ

task: 目的を参照する仕組みの追加とnote紹介の改稿
area: explanation
contribution: 書きながら考えを深める生成を中心に戻し、推敲との関係を説明する
non_goals: 生成方式の変更、全一般原稿への目的宣言、公開、配布済み環境の更新

noteは各節に比較例を残しますが、推敲の前後だけでなく、最初の見方と書いた後の続きを比べます。説明用の仮定と実際の生成実験を区別します。

## 未検証の範囲

コードのテスト、互換性検証、目的逸脱の減少についての実測は未実施です。正本を要求へ渡すことと、必ず目的を守ることを混同しません。
