# 節と段落の分離

目的: 各段落に説明・例・留保・まとめを要求する均質化を避ける。
原因: 従来は表示ブロックの役割だけを記録し、段落境界と節のまとまりを独立に扱っていなかった。指示だけの「長さをそろえない」では、同じ仕事を繰り返す生成を防げなかった。
採用: 一節は一つの問い、段落は対象・視点・時間・役割の変化などで切る。字数や段落数は可変。仮見出し→複数段落の本文→結論的な最終見出し→残りの構成の更新。
見送り: 長短交互、字数の乱数化、分散の合格閾値、毎段落に小見出し、全段落の起承転結。
最終小見出しは13文字以内、句読点を禁止。実装では空白を除いたNFC文字列を数え、Unicodeの句読点・記号的な句切りに当たるPカテゴリも拒否する。記事タイトルは小見出しの13文字制約と別扱い。
新しいeditor-requestをv3とし、段落境界と節の再考記録を必須にする。v1/v2保存済み要求は従来契約を維持。各節の本文IDは見出し直後から次の見出し直前までの表示ブロックと一致させる。
指示文は参照先ファイル名だけでなく、必要な同梱編集ルール本文を要求に含める。JSONだけを渡した場合にも今回の規則が届くようにする。
限界: 記録の構造と見出し書式は機械で扱うが、結論らしさ、段落を切る妥当性、生成の実時間順序は証明しない。本文の均質化が解消したという読者評価は未取得。
完了条件: 契約と共通指示の更新、比較用改稿と判断記録、既存note下書きへの反映。今回はコードのテスト・検証は実行しない。改稿はルールを適用した編集でありeditor-applyの受理実績とは区別する。
