# natural-japaneseをbunmyakuに同梱する

## 目的と完了条件

2026-09-15。bunmyaku単体の導入でnatural-japaneseの執筆指針、参照資料、通常の検査を使えるようにする。別のnatural-japaneseスキル、開発者のホームディレクトリ、uvの事前導入に依存しない。Python 3.11以上と利用するAI環境は従来どおり必要。検査の初回には依存パッケージ取得の通信を使う。

隔離した導入先でlint・outline・termsが動き、JSON出力と入力エラーが保たれること、配布物に資料とライセンスが入ること、執筆担当と点検担当が統合手順を受け取ることを完了条件とする。既存スキルや利用者の記憶を上書きしない。実読者への品質改善は今回の完了条件に含めない。

## 現状と原因

配布はjlangbase内のPython・Markdown・JSONを収集するが、natural-japanese本体は外部のスキルディレクトリにしかない。writing-taskは共通手順を渡すが、このスキルの手順や検査結果を含めない。さらにwheelのpackage-dataはresources直下のみで、階層を持つ資料を指定する必要がある。元スクリプトはSudachiPyと辞書に依存し、単純なコピーでは未導入環境で検査できない。

## 採用する構成

resources/natural-japanese/に上流SKILL.md、references、assets、scriptsとLICENSE.md、由来のJSONを置く。キャッシュやコーパスは取り込まない。元スクリプトの意味を変えず、共通CLIの実行アダプターで依存を解決する。通常の検査はSudachiPyとSudachiDict-coreだけ。semanticの実験依存とモデルは通常検査から分離する。

通常検査の初回実行では、端末内の専用仮想環境を作り、固定した依存を導入する。システムPythonや既存スキルを変更しない。準備失敗は再実行可能なエラーにし、不完全な環境を準備済みとしない。ネットワーク待ちと検査実行に内部上限を設ける。

natural-japanese-workflow.mdを統合手順とする。文体と素材の指示は依頼を優先し、bunmyakuの生成・委譲・保存契約を維持する。上流の「結論を先に決める」は暫定主題として扱い、記事の発見で更新できる。リズムの数値目標や自己採点を合格条件にせず、記録の一律削除を適用しない。上流の追加委譲を担当内で再帰実行しない。

## 実装と検証の順序

資料の固定と同期手段、検査アダプターと依存準備、配布・context・執筆工程への接続、規則と利用手順、隔離導入検証の順に進める。別の担当が配布と依存の失敗条件を確認する。仕様との整合と実行結果は完了時に追記する。

## 実装結果

上流commit cecd53e98d58ab8ba7d9f97a9f4558362d643c5aを採用し、原文のまま24ファイルとprovenance.jsonを同梱した。MIT表示、各ファイルのSHA256、除外理由を含む。同期スクリプトは元リポジトリの未確定変更、同梱先の独自変更、シンボリックリンクを拒否する。同梱スクリプトの実行で生成されたキャッシュは判定と配布から除外する。

context、共通CLI、配布スキル、writing-task、配布時の記憶と索引へ接続した。Ollamaを含む点検要求へ三検査の実結果を渡す。保存状態とレビューの合否形式は維持し、警告数で判定しない。
