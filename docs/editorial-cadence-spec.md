# 素材生成と読者向け編集を分ける

## 原因と目的

note初稿では、生成ループの各段落に説明・例・留保・発見を詰め、その20段落をそのまま表示段落にした。判断材料を十分に生成する工程はあったが、読者に渡す情報を選び直す工程がなかった。長さだけの問題ではなく、思考の単位と読者が理解する単位を同一に扱ったことが原因仮説である。ユーザーは情報の取捨選択、段落長の均質さ、内声でのリズムの崩しと立て直しを指摘した。

## 採用する仕様

1. editor-requestで原稿、読者、タイトルの約束、保持要件、追加資料を固定した編集要求を作る。
2. editor-selectで全素材にkeep/compress/move/dropを割り当てる。理由と失うものを必須にし、書き換える前に選択を記録する。
3. editor-applyで素材と別のIDを持つ表示段落を受け取る。統合・分割・順序変更を許し、元の生成状態は変更しない。
4. 表示段落は役割と読者が得る理解を持つ。保持要件は本文引用へ対応付ける。捨てた素材の参照、未知のID、引用不一致、無記録の脱落、keep/moveの文面変更は受理しない。
5. 音の検討は必要箇所だけ。基調・ずれ・落ち着き先を引用で指定し、順序、意味上の役割、別案と採用理由を記録する。全段落にこの型を要求しない。変更不要なら理由だけでよい。
6. 文字数と文長は記述統計として返す。音数、快さ、品質点とは扱わない。音の検討はtext_inferenceとし、AIが実際に発声・聴取したとは記録しない。
7. 受理結果はeditorial_candidate。意味の妥当性と読者の快さは未判定で、品質向上のフラグはnull。

## 見送った案

- 段落文字数の上限・ばらつき目標: 内容を選ばず形だけ変えるため不採用。
- 五七調への自動整形: 休止や語境界、文章の意味を無視するため不採用。
- 全段落の起承転結・短長短の固定: 均質な鋳型を置き換えるだけなので不採用。
- 削除率の最大化: 必須情報や作者の声を失うため不採用。
- 音楽の逆U字を作文の目的関数にする: 刺激・課題差と反例があるため不採用。
- TTSの一発採点: 読み手の内声の代用としては保証できず、今回導入しない。
- 生成ループそのものの多段落化: 既存の履歴形式を壊す変更を避け、今回は表示単位を後段で分離する。深い思索の継続条件は別課題。

## 完了条件と範囲

共通CLIから編集の三段階を使え、スキルの共通手順から案内されること。note記事は新工程を実行して候補を作り、既存下書きを更新する。Ollamaの既存コマンドが編集まで自動完走する変更は今回含めない。新しい処理のテスト・独立評価・音声による検証は未実施。処理の実行成功は品質向上の証明ではない。

グローバルの~/.agents/references等とnote作業フォルダは現権限で書き込めない。ルール・薄いスキル入口・判断の記憶と索引はリポジトリ内へ残す。個人の原稿や判断台帳はoutput配下で公開対象にしない。
