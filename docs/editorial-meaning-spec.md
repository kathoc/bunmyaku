# 編集v2: 記事全体の選択と、意味を受け取る時間

## 問題と原因仮説

前回の編集は段落単位でcompress/dropを選び、長さを減らした。しかし短縮しても概念の切り替わりが減らず、理解の負担は残った。重複する注意書き等を削る原則が、読者が意味を受け取り直す反復まで削る方向に働いた。字数や出典対応の記録だけでは、説明が何を支えているかを扱えない。

## 採用する仕様

新規editor-requestはeditorial_version=2。選択の前に記事の主張、読後に分かってほしいこと、節ごとの問い・答え・貢献・依存関係を宣言する。原文は段落だけでなく引用を伴う意味単位へ分け、役割、採否、理由、失うもの、代案と見送った理由を記録する。

採用した意味が依存する前提を削る選択、対応する材料がない節、全ての意味を削ったのに段落はkeepとする選択は拒否する。再構成後は採用した意味を新しい本文の引用へ対応付ける。文字列の検査は意味の妥当性の証明ではない。

表示段落ごとにfocus、前から引き継ぐ意味、導入する概念、理解を落ち着かせる概念、前後との関係を記録する。新しい対象へ移る場合は入口を説明する。新概念の固定上限は設けない。モデルの自己申告である以上、概念数そのものを認知負荷の測定値とは呼ばない。

echoは有益な反復として扱う。前後の意味、視点の変化、読者に与えたい効果、追加した主張、根拠を記す。同じ話題だから同じ意味とは判定しない。状況から人の経験へ移すとき等、新しい推論を加える場合は保持した根拠のIDを要求する。不明な推論は受理せず資料に戻す。

## 採否判断の順序

1. 題名の問いに対する答えと、その理解に必要な道筋を決める。
2. 中核の主張、その根拠、具体例、誤読を防ぐ留保を見分ける。
3. 各部分を外した場合、どの理解・納得・声・呼吸が失われるかを考える。
4. 削除だけでなく、移動・圧縮・具体化・言い換えて残す案を比べる。
5. 意味を受け取る足場を残したうえで再構成する。

## 不採用

- 新語数の一律上限: 既知語や文脈による違いを扱えない。
- 語の一致率による同義判定: 視点の変化と根拠のない推論を区別できない。
- 反復の一括削除・毎段落の言い換え義務: どちらも新しい均質な型になる。
- 常に短い案を採用: 情報を詰め直すだけの圧縮を招く。
- 全文を固定した構成へ従属させる: 生成中の探索は維持し、ここは生成後の編集判断に限定する。

## 互換性と完了条件

v1の既存要求は従来の配列形式を受け付ける。v2はstrategyとdecisionsのオブジェクト形式を必須にする。新規要求の利用者は新しい手順に沿う必要がある。共通CLIの入口は変更しない。思考の生成履歴やnoteの旧原稿は今回書き換えない。

機械的な検査と編集者の判断を分離した実装を追加。品質向上の結果は引き続きnull。テスト・独立した意味評価・noteへの適用・GitHubへの反映は今回未実施。
