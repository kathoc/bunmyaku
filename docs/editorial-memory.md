# 編集工程についての記憶

2026-09-07。note初稿への指摘: 内容の割に段落が長い。段落長が均質。書き殴りから取捨選択する判断が必要。作者は頭の中で発音し、リズムの崩れと立て直しにも快さを感じる。

再現する方針: 生成段落と表示段落を別の単位にする。素材ごとの採否と損失を先に記録し、保持要件を新しい本文へ対応付ける。長さや音数の目標値を埋めない。文字上のリズム推定と実際の発声・読者の快さを混同しない。

## 意味を受け取る時間と選択の粒度

同日追記。作者は、短い範囲で対象や概念が次々に入れ替わる文章を読みにくいと指摘した。状況を人の経験へ捉え直すような、有益な言い換えは冗長とは限らない。短縮優先の方針を改め、記事全体の問いから意味単位へ選択を下ろし、理解に必要な前提・具体例・留保・声を残す。参照: docs/editorial-meaning-spec.md、resources/editorial-meaning.md。v2の実装は独立した意味評価を行うものではない。

## 標準文体

2026-09-07、利用者の指定により、新規執筆の標準を「だ・である」調ではなく「です・ます」調とする。明示的な文体指定や既存原稿の文体保持は優先する。共通手順とスキル入口へ反映。既存記事の一括変換を意味する指示としては扱わない。

## 敬体を全ての文の語尾にしない

ユーザー指摘: note記事に「す」で終わる文が多い。語尾だけを交換せず、説明の重複、文の接続、切り方から直す。記事の観察や独り言には常体を許すが、敬体を基調とし、厳密な文体指定を優先する。効果の読者評価は未取得。正本: src/jlangbase/resources/editorial-register.md。実装範囲: 指示層、JSON契約は不変。
