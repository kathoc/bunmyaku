# curlによる導入

## 目的と採用方針

配布物の手動ダウンロード・展開を不要にする。既存のPythonインストーラーに処理を集約し、シェル側で登録処理を重複させない。

macOS・LinuxにはPOSIXシェルとcurl、WindowsにはPowerShell 5.1以降の専用入口を採用する。どちらもPython 3.11以上を必要とし、既存のPythonインストーラーへ処理を渡す。WindowsではGit Bashを必要としない。Python自体の自動導入は、OSの管理方法や権限を勝手に変更しないため行わない。

## 要件と完了条件

- HTTPSで公開リポジトリのmainのZIPを取得し、必要なソースだけを一時フォルダへ展開してinstall.pyを実行する。
- ダウンロード失敗、不正なアーカイブ、Python不足では停止する。終了時は一時フォルダを削除する。
- インストーラーの引数と終了コードを引き継ぐ。個人履歴を送信せず、sudoを要求しない。
- READMEの最初の導入手順をcurl方式にする。実行前にスクリプトを読む方法も案内する。
- --updateは明示的な更新であり、定期改善や自動更新と混同しない。
- PowerShellは-Update、-Tools、-InstallHome、-DryRunをPythonの対応する引数へ変換する。取得・展開・導入の失敗は例外として報告し、終了時は一時フォルダと通信設定を後始末する。実行ポリシーは変更しない。

## 制約と作業記録

公開mainの最新版を取得する方式であり、署名検証や固定バージョン指定は今回の対象外。HTTPSは配信元への信頼を置き換えない。シェルの入口とZIPは別のリクエストなので、同一コミットの保証もない。

READMEと導入案内を更新し、古い中央改善の案内は現在の端末内方針へ置き換える。実行テスト、実インストール、各OSの動作確認は未実施。GitHubへ反映するまでは公開URLから新しい入口を利用できない。
